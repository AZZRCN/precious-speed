## 1. 一句话

**FFT 变换长度目前只能取 2 的幂。把可用长度扩展到 `r·2^m`（r∈{3,5,9,15,25,27,45}），
在"完全不放松精度"（保持现有无符号表示、保持 `k` 不变）的前提下，
官方测试集的 FFT 总工作量下降 ~10.7%，折合总墙钟 ~−5%。
这是当前已验证的最大单项、且正确性零风险的优化。**

## 3. 全官方集收益（工具 `lenplan.py` 实测，正确数据集）

工作量代理 = Σ `3·L·log2(L)`。`now` = 现役纯 2 幂；`mix` = 扩展基但**保持 `2^48` 精度预算（无符号，零风险）**；
`bal` = 平衡(有符号)表示（预算放宽到 `2^50`）；`bal+mix` = 二者叠加。

| 方案 | 总 FFT 工作量下降 |
|---|---|
| `mix`（默认基 {2,3,5,9,15,25,27,45}） | **−10.66%** ← 本任务目标 |
| `mix`（仅 {2,3,5,9,15}） | −9.93% |
| `bal`（仅换表示，长度仍 2 幂） | −0.77%（几乎无意义） |
| `bal+mix`（换表示 + 扩展基） | −19.62% ← 见 §10 进阶，高风险 |

**墙钟折算**：`perf` 剖析显示 FFT 蝶形占 `max_max` 的 53%、22 点聚合的 44%。
故 `mix`（−10.7% FFT 工作量）≈ **−5% 总墙钟**；其中 10 个最大点（LC 计分由 `max_max_06` 主导）各 −6.3% FFT ≈ −3% 墙钟。
`bal+mix`（−19.6%）≈ −9% 墙钟，但需改核心数值表示，风险高。

## 4. 要改什么

现役 FFT 是 **radix-4 自排序（self-sorting）AVX2 浮点 FFT**，
`__m128d` 装一个复数，`difRec`/`ditRec` 递归分解。
核心代码见 `_fft_core.txt`（只读快照参考）。

交付：
### 4.1 长度选择器（在已修正版上扩展）

```cpp
// 现役（我方已合入的严格版，起点）：
static inline u32 fft_len_for(size_t u, int k) {
    const u32 c = (u32)((u * 64 + (size_t)k - 1) / (size_t)k);
    return (c & (c - 1)) ? (2u << (31 - __builtin_clz(c))) : c;
}
// 目标：返回 >= coeffs 且形如 r*2^m (r ∈ RADIXSET) 的最小 L，
//       且必须满足 2^(2k) * L <= 2^(2k) * L_pow2（即不放松精度）。
// 推荐枚举：对每个候选 m 取最小够用的 r，再取全局最小 L。
// 注意：L 必须在 coeffs 与 2^20(=1048576, 现役 LMMAX) 之间。
```

### 4.2 混合基分解层

长度 `L = r·2^m`（r 为奇基）时，在递归顶层做一次 radix-r 分解，
得到 r 个长度 `2^m` 的子变换走现有 radix-4 路径。DIF 与 DIT 各需一份。
r=3/5/9/15 用 Winograd 小 DFT；r=25/27/45 可拆成 radix-5×5 / 3×9 / 5×9 两级。

**radix-5 蝶形（DFT-5，Winograd 形式，仅需 2 组实乘常量）：**
```
c1 = cos(2pi/5) =  0.3090169943749474
c2 = cos(4pi/5) = -0.8090169943749474
s1 = sin(2pi/5) =  0.9510565162951536
s2 = sin(4pi/5) =  0.5877852522924731
t1 = x1 + x4;  t2 = x2 + x3;
m1 = x1 - x4;  m2 = x2 - x3;
y0 = x0 + t1 + t2
a  = x0 + c1*t1 + c2*t2
b  = x0 + c2*t1 + c1*t2
p  = i*(s1*m1 + s2*m2)
q  = i*(s2*m1 - s1*m2)
y1 = a - p;  y4 = a + p;
y2 = b - q;  y3 = b + q;
```
约 17 次复加 + 4 次实×复乘。`i*z` 用 `shuffle + xor 符号位`，不要真乘。

### 4.3 旋转因子（twiddle）

混合基层之后，第 j 个子变换要乘 `W_L^(j·t)`。
现有两级 twiddle 表（`w1[j]*w2[t]`，把表从 `L` 降到 `~2√L`）**直接照搬**。
⚠️ `L≈1e6` 的完整表是 ~20 MB，会打爆 LLC，必须用两级表。

## 5. 硬约束（违反即作废）

1. **编译口径固定**：`g++ -O2 -march=x86-64-v3 -std=c++23`。
   禁止 `#pragma GCC optimize`、`-O3`、`-ffast-math`、PGO。
2. **不得放松精度**：新 `L` 必须满足 `2^(2k)·L_new ≤ 2^(2k)·L_old`（即 `L_new ≤ L_old`）。
   §3 的 `mix` 收益全在此约束下，无需冒险。
3. **`merge` 判据 `max|g[j]−round(g[j])| < 0.25`** 必须保持；交付附实测 max_err。
4. **单线程**，禁止 OpenMP/多线程。
5. **禁止 AVX-512**（Zen3 无）。

## 10. 进阶（可选，高风险高回报）：平衡(有符号)表示 + 混合基

若 Phase 1 的 `mix` 已合入且零回归，可进一步把 limb 系数从 `[0,2^k)` 改为
`[−2^(k−1), 2^(k−1))` 的**平衡表示**：
- 误差项降 4×（有符号乘法误差更小），精度预算从 `2^48` 放宽到 `2^50`；
- 在**不放松实际精度**的前提下，等于白送 1 bit 的 `k`，让 `r·2^m` 能取更小 `L`。
- 例：`max_max` 从 `2^20 (k=14)` → `27·2^15=884736 (k=15)`，工作量再降 16.7%。

`bal+mix` 合计 **−19.6%** FFT 工作量 ≈ **−9% 墙钟**。

⚠️ 风险：改变核心数值编码，影响 `split_b2` 位分割、点乘、merge 进位恢复。
必须配**大规模随机压测 + 精度余量 + 22 点 `.exp`** 三重闸门，且严格 A/B 对拼 Phase 1 版本。
建议作为独立后续任务，不要与 Phase 1 混改（否则归因困难）。
