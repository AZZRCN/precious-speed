# VM Benchmark 2026-07-20

## 环境
- VM: `192.168.1.55` (Ubuntu 26.04 LTS, kernel 7.0.0-28-generic)
- Compiler: `g++ (Ubuntu 15.2.0-16ubuntu1) 15.2.0`
- CPU: 11th Gen Intel(R) Core(TM) i7-11370H @ 3.30GHz (2 vCPU, VMware 虚拟化, AVX2=✓, AVX-512=✓)
- Memory: 3351 MiB
- `CLK_TCK` = 100 (=> `/usr/bin/time -v` User time 粒度 = 10.0ms)
- 编译: `-O2` / `-O3` + `-std=gnu++20 -static -DONLINE_JUDGE -DHINT_OP_{ADD,MUL,DIV}`
- 源文件: `moptm_fusion.cpp` (moptm v2 融合优化最终版)
- 数据: ADD=1M+1M, MUL=500k*500k, DIV=1M/500k, DIV=200k/100k (除数最高位 5-9 保证归一化)

## 测量方法
- 5 次 bash 内置 `time` 调用, 取中位数
- 每次调用内 bash 循环 LOOPS=50 次, 计算 `per_run = total_user_seconds * 1000 / 50`
- bash 内置 `time %U` 给出 user CPU 时间, 精度 1ms; 50 次循环使等效 per_run 精度达 1ms/50 = 0.020ms
- 这样解决了 `/usr/bin/time -v` 的 10ms 粒度问题 (因 `CLK_TCK=100`)
- per_run 含二进制启动+I/O 的总单次 user CPU 时间 (静态链接, 启动开销 ~0.2ms)
- DIV 1M/500k 与 DIV 200k/100k 共用 `moptm_div` / `moptm_div_o3` 二进制
- 最大 RSS 由单独的 `/usr/bin/time -v` 单次运行测得

## 说明
- User time = 用户态 CPU 时间 (不含内核态/IO 等待), 由 bash 内置 `time` %U 给出
- 程序使用 mmap 零拷贝读 stdin, 必须用文件重定向 `< file` (不能用管道)
- 5 次中位数 = 排序后第 3 个值
- 正确性已通过 `wc -c` 输出字节数粗验 (ADD ≈ 1M+1 字节, MUL ≈ 1M+1, DIV = q+' '+r+'\n')
- **粒度问题说明**: `/usr/bin/time -v` 的 `User time (seconds)` 在 Linux 上以 clock_t 为单位; 本 VM `CLK_TCK=100` 即 10ms 粒度, 对 sub-10ms 操作 (如 ADD/MUL) 直接测会显示 0.00ms. 本测试改用 bash 内置 `time` (1ms 精度) + 循环 50 次, 使等效 per_run 精度达 0.02ms
- 对比源码注释 (yosupo judge 不同硬件): ADD 1M 14.1ms / MUL 500k 16.8ms / DIV 1M 37.1ms — 本 VM (i7-11370H) 因 CPU 更快而显著低于上述数值
