## 1. 背景与硬约束（不可违背）

- **题目**：Library Checker #393027，HEX 大整数除法。规模 `LOG_16 ≈ 1.6e6`（与 DEC 道 `LOG_10=2e6` 同量级 bit）。当前战场是 `div.cpp` 的除法核 `absDivMu` / `length_ratio_integer_2`。
- **权威度量 = 指令数 Ir（callgrind）**：
  - 唯一真值来源。`perf stat -e instructions:u` 在 VMware 客户机（无虚拟 PMU）下报 "No supported events found"，不可用。
  - callgrind 软件计数在 VM 内有效；Ir 在 x86-64 二进制下 **Intel/AMD 一致**（微码不改原始指令条数），故本地 VM(Intel) 的 Ir 结论对 AMD 方向直接有效。
  - **禁止墙钟计时 / cycles / IPC 作为优化决策依据**（抖动大，非真值）。
- **2^52 精度墙（核心天花板）**：
  - 核心用 `double` 做 FFT 大数乘。double 尾数 52 位（含隐位 53），卷积中间和须 `< 2^52` 才保精确 → **单次 FFT 长度 `n ≤ 2^21`**，单 limb 位宽 `w` 与 `n` 被此墙钉死。
  - 凡"改尺寸 / 改 limb 基 / 复用牛顿"的方案，都受此墙约束，前期多数已被证伪或净亏。
- **语言与实现**：运行时热路径必须 **C++**（排斥 Python）；编译 `-O3 -march=haswell -std=gnu++17`。
- **内存上限**：LC 法官环境有限。当前单级大表 + 32 槽缓存实测总占用几 MiB 量级，远未触顶；新方案须自证不爆内存。
- **铁律**：一切上实测。任何假设须经 **bytecmp（逐字节正确性）+ callgrind Ir（指令数真值）** 两道闸门，不靠推理自洽。

4. **混合算法分界点重估**
   - 大尺寸走 FFT、小尺寸走 schoolbook / Karatsuba / Toom 的分界点是否最优？不同规模段用不同 limb 基是否划算？**所有此类须过 Ir 闸门，不可凭推理。**
