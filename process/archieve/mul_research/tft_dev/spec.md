## 1. 洛谷 XFT 算法调研报告

### 1.1 调研来源

- 洛谷 P3803（多项式乘法 FFT 模板）题解

### 1.2 XFT 变种核心思想与可借鉴点

| XFT 变种 | 核心思想 | DFT 次数 | 适用场景 | 对当前 mul.cpp 的可借鉴性 |
|----------|----------|----------|----------|---------------------------|
| **FFT** (基础) | 复数 DFT，Cooley-Tukey 蝶形 | 3 (2 DFT + 1 IDFT) | 通用多项式乘法 | 已实施 split-radix 版本 |
| **NTT** | 整数模 DFT，避免浮点 | 3 | 带模数的多项式乘法 | 不适用（LC 大数乘法无模数） |
| **三模 NTT + CRT** | 3 个 NTT 友好素数（998244353, 1004535809, 469762049）+ CRT 合并 | 9 (3×3) | 任意模数多项式乘法 | 不适用（增加常量因子，无模数场景） |
| **MTT 拆系数 FFT** | F(x)=bas·A(x)+B(x)，拆系数降低值域，4 次子乘法 + 合并 | 8 (4 DFT + 4 IDFT) | 任意模数（精度不足时） | 思想已部分应用（实数 DFT 共轭打包） |
| **MTT 4次DFT 优化版** | 实虚部打包 + 共轭对称性恢复 + IDFT 实虚部合并 | 4 (2 DFT + 2 IDFT) | 任意模数（AzusaCat 版） | **当前 mul.cpp 已实施等价优化** |
| **三次变两次优化** | G(x) 放 F(x) 虚部，求 F(x)²，取虚部除 2 | 2 (1 DFT + 1 IDFT) | 仅平方（a=b） | 自平方路径 `absSqr` 可借鉴 |
| **FWT** | 沃尔什-哈达玛变换 | - | 异或卷积等 | 不适用（非乘法场景） |
| **TFT** (van der Hoeven 2004) | 递归剪枝蝶形，避免 padding 浪费 | ~m/n × 3 | 输出长度非 2 的幂 | **本项目核心创新点** |
| **迭代 FFT + 位逆序置换** | 栈开销消除 + 预计算重排 | 3 | 通用 | 已实施（dif/idit 迭代版） |
| **预处理单位根表** | 预算 cos/sin 表，避免重复计算 | 3 | 通用 | 已实施（`expand` 机制） |

### 1.3 关键洞察

**洛谷文章的优化焦点**：减少 DFT 次数（3→2，9→4），主要面向带模数多项式乘法。

**当前 mul.cpp 的现状**：
- 实数 DFT 共轭打包（等价于 MTT 4次DFT 优化的核心思想）已实施
- split-radix + AVX2 向量化已实施
- 迭代化 + 单位根表预计算已实施
- **DFT 次数已压到极限**：实数乘法只需 1 次复数 DFT（打包 a,b） + 实数点积 + 1 次复数 IDFT

**剩余可借鉴点**：
1. **三次变两次优化**（仅自平方路径）：`absSqr` 可从 3 次 DFT 减为 2 次 DFT，但当前已用共轭打包，需实测验证收益
2. **拆系数精度保障**：当 limb 值域更大时（如 base=10^9），拆系数可避免精度损失。当前 base=10^4 精度足够，但若未来切换 base 可借鉴
3. **预处理单位根表精度**：long double 替代 double。当前用 double，精度足够，不切换

**真正能"打败他们"的突破点**：
- 洛谷文章大多停留在"减少 DFT 次数"层面，**未涉及算法结构创新**
- TFT（截断傅里叶变换）是真正"思路不同"的算法，洛谷文章几乎无人深入
- **本项目核心差异化**：TFT 算法结构创新 + Karatsuba 中规模快速路径 + 交错 DFT 缓存优化

## 3. TFT 算法核心理论

### 3.1 算法起源

由 Joris van der Hoeven 2004 年在论文《Truncated Fourier Transform and Homogeneous Multiplication》中提出。GMP 开发邮件列表曾讨论将 TFT 用于 NTT 乘法以减少 transform size。**洛谷文章几乎未涉及 TFT**，是本项目差异化竞争点。

### 3.2 核心思想

传统 Cooley-Tukey 分解：
```
DFT_n(a) = DFT_{n/2}(a_even) + W_n^k * DFT_{n/2}(a_odd)
```

**TFT 剪枝原理**：若只需输出前 m 个 DFT 系数（m < n），递归分解后：
- `DFT_{n/2}(a_even)` 需计算 `min(m, n/2)` 个输出
- `DFT_{n/2}(a_odd)` 需计算 `max(0, m - n/2)` 个输出
- 递归剪枝不影响输出前 m 项的蝶形

**复杂度**：`O(m * log(n))` vs 传统 `O(n * log(n))`，当 `m << n` 时显著节省。

### 3.3 乘法流程对比

**传统 FFT 乘法**（当前实现）：
```
1. float_len = int_ceil2(conv_len)         // padding 到 2 的幂
2. DFT_n(a)                                  // n = float_len，计算全部 n 个系数
3. DFT_n(b)
4. c_k = a_k * b_k                           // n 个点积
5. IDFT_n(c)                                 // 全部 n 个系数逆变换
```

**TFT 乘法**：
```
1. n = int_ceil2(conv_len)                   // 仍需 2 的幂作为递归基
2. TFT_n^m(a) where m = conv_len             // 只计算 DFT(a) 前 m 个系数
3. TFT_n^m(b)
4. c_k = a_k * b_k for k in [0, m)           // m 个点积
5. ITFT_n^m(c)                               // 从 m 个 DFT 系数恢复时域前 m 项
```

### 3.4 ITFT (Inverse TFT) 关键挑战

ITFT 需要从**部分**频域系数恢复时域序列，传统 IDFT 公式 `a_k = (1/n) * sum_j c_j * W_n^{-kj}` 在 `j` 不完整时无法直接使用。van der Hoeven 给出了基于递归剪枝的逆向算法，但实现复杂度高。

## 4. 关键风险：TFT 收益预估

### 4.1 padding 浪费分析

当前 `fftMul` 中 `float_len = int_ceil2(conv_len)`，padding 浪费 = `float_len - conv_len`：

| 用例 | conv_len | float_len | padding 比 | TFT 节省比 | 单 query FFT 量 (×3) | 文件加权 FFT 量 | TFT 收益 |
|------|----------|-----------|------------|-----------|----------------------|------------------|----------|
| max_max × 8 | 1M-1 | 1M | 0.0001% | ~0% | 60M | 480M | ~0M |
| fft_killer × 2 | 1M-1 | 1M | 0.0001% | ~0% | 60M | 120M | ~0M |
| large × 3 × 36 | 49K-1 | 64K | 23% | ~12% | 3M | 324M | ~39M |
| large_small × 2 | 500K-1 | 512K | 2.3% | ~1.2% | 30M | 60M | ~0.7M |
| medium × 3 × 4000 | 499 | 512 | 2.5% | ~1.3% | 14K | 166M | ~2.2M |

**TFT 单独加权收益估算**：`(0 + 0 + 39 + 0.7 + 2.2) / (480 + 120 + 324 + 60 + 166)` ≈ **3.6%**

### 4.2 风险声明

**TFT 单独使用预估收益 3-5%，达不到 10% 硬性阈值**。主要原因：
- max_max/fft_killer 占总耗时 ~52%，但其 conv_len 恰好接近 2^20，padding 浪费接近 0
- TFT 的收益与 padding 浪费成正比，对 2 的幂附近的长度无效

### 4.3 补救方案：TFT + 组合优化

为达到 10% 阈值，必须 TFT 与其他算法组合：

| 方案 | 组合项 | 预估增量 | 总收益 | 复杂度 |
|------|--------|----------|--------|--------|
| A | TFT + Karatsuba 中规模快速路径 (64-2048 limbs) | +2-3% | ~6-8% | 中 |
| B | TFT + 双 DFT 交错执行（改善缓存局部性） | +3-5% | ~7-10% | 高 |
| C | TFT + 蝶形层折叠（更激进剪枝） | +1-2% | ~5-7% | 中 |
| D | TFT + Karatsuba + 交错 DFT + 三次变两次(平方) | +5-8% | ~9-13% | 高 |

**推荐方案 D**：TFT 基础 + Karatsuba 中规模 + 交错 DFT + 自平方路径三次变两次优化，目标 9-13% 总收益，覆盖洛谷 XFT 文章的所有可借鉴点。

## 8. 关键决策点（需用户审阅批准）

### 决策 1：TFT 收益预估不足 10%，是否继续？

- 选项 A：按推荐方案 D（TFT + Karatsuba + 交错 DFT + 三次变两次）继续，目标 9-13%
- 选项 B：放弃 TFT，重新讨论算法方向（如多模 NTT 或 Toom-Cook）
- 选项 C：仅做 TFT 理论原型验证（不强求 10%），作为长期储备

### 决策 2：实施优先级

- 选项 A：先 Python 原型验证理论，再 C++ 实现（推荐，风险低）
- 选项 B：直接 C++ 实现，跳过 Python 原型（速度快，风险高）

### 决策 3：集成策略

- 选项 A：XFT 作为 `real_conv` 的并行路径，运行时按 conv_len 切换
- 选项 B：XFT 完全替换 `real_conv`，原 FFT 代码作为回退保留

### 决策 4：洛谷优化思想吸收范围

- 选项 A：仅吸收 TFT（算法结构创新），其他洛谷优化已实施或已评估
- 选项 B：TFT + 三次变两次（自平方路径）+ Karatsuba + 交错 DFT 全部吸收
- 选项 C：先实施 TFT，根据实测收益决定是否吸收其他优化
