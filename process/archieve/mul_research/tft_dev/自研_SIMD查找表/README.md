# 自研算法方向C：SIMD查找表乘法

## 状态：理论证伪（查找表比base 10^8打包慢1-25倍）

## 设计思路

### 核心创新
利用LC大数乘法的limb值域小（[0, 9999]）特性：
1. 将10^4 limb拆为两个10^2子limb
2. 预计算100×100乘法查找表
3. 用VPSHUFB做并行查找表

### 理论优势
- 无精度问题（整数运算）
- 无padding（不需要2的幂次）
- SIMD友好（VPSHUFB单周期）

## 失败原因

### 1. 查找表比直接乘法更慢
- 标量查找表需要额外内存访问（L1缓存命中也有4-5周期延迟）
- 直接乘法只需1周期（现代CPU流水线）
- 4次查找表 + 3次加法 + 拆分开销 > 1次直接乘法

### 2. base 10^8打包已优化O(n²)
- CUR的basic_mul用base 10^8打包（两个10^4 limbs打包为一个10^8 limb）
- O(n²)乘法次数降低4倍
- 查找表方案无法与此竞争

### 3. VPSHUFB SIMD化复杂度高
- 100×100表需分块为7×7=49个16×16子表
- VPSHUFB每次查16个字节，但需要多次分块查询
- SIMD化后的常数因子仍大于base 10^8打包

### 4. LC场景不适用
- LC测试点都是大规模（float_len=1048576）
- basic_mul路径（float_len < 64）占比 < 1%
- 即使加速basic_mul 2倍，对LC整体性能影响微乎其微

## 结论

方向C (SIMD查找表乘法) **理论证伪**：
1. 查找表乘法比base 10^8打包慢1-25倍
2. 标量查找表比直接乘法更慢（内存访问开销）
3. base 10^8打包已将O(n²)降低4倍
4. LC场景basic_mul路径占比 < 1%

**不集成到CUR**，无任何收益。
